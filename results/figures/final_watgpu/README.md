# Final figures

Primary run: `gist1m_20261110_003629` (timestamp 2026-11-10T00:40:14). Generated by `scripts/generate_final_figures.py --run-id gist1m_20261110_003629 --comparison-run gist1m_20261110_004019`.

Every plotted value is listed with its source column in `plotted_values.csv`. No values were averaged across runs; the comparison run is used only in `latency_stability.*`.

## Setup

* GIST1M: 1,000,000 database vectors, 100,000 training vectors, 1,000 queries, d = 960, L2.
* nlist = 1024, PQ nbits = 8, nprobe = [1, 4, 16, 32], k = 100.
* 4 FAISS threads, 5 timed repetitions after warm-up.
* Latency: one query per search call, per-query timing; p50/p95 computed per repetition, median over repetitions reported (ms/query).
* Throughput: all 1000 queries in one call; median QPS over repetitions.
* Index size: bytes of the serialized `.faiss` file (MiB = 2^20 B, GiB = 2^30 B).
* Exact-1NN Hit@100: fraction of queries whose exact nearest neighbour appears anywhere in the approximate top-100. Not Recall@100. Computed by `scripts/compute_exact1nn_hit.py` from the run's cached indexes (no timing); that script verified Recall@1/10/100 equal the run's recorded values exactly before saving `gist1m_20261110_003629_exact1nn_hit100.csv`.

## Latency caveat

Latency was measured on Intel(R) Xeon(R) Gold 5415+, 607 GiB RAM, host watgpu208, SLURM job 1681750, 8 CPUs allocated. Bytes swapped in (system-wide counter) while each index was being searched:

| index | swap-in during search |
|---|---|
| IVF-Flat | 0 MiB |
| IVF-PQ (16 B) | 0 MiB |
| IVF-PQ (32 B) | 0 MiB |
| IVF-PQ (64 B) | 0 MiB |

No swapping occurred during timed search.

Measured latencies were not modified, corrected or filtered. Absolute latencies should be interpreted with care; the comparison between indexes is the more reliable signal.

Two independent 5-repetition runs (`gist1m_20261110_004019` and `gist1m_20261110_003629`) gave identical recall for all 16 configurations and very similar latency:

* p50 latency: run-to-run difference median 8.6%, max 27.7%.
* p95 latency: run-to-run difference median 20.4%, max 31.9%.
* The ordering of indexes by latency is the same at every nprobe in both runs: no (see latency_stability).

## Interpretation note

IVF-Flat Recall@10 keeps rising with nprobe while IVF-PQ Recall@10 flattens from nprobe = 16. The observed plateau is consistent with quantization error becoming the dominant source of retrieval error once IVF candidate coverage is sufficient; it is not a causal proof.
